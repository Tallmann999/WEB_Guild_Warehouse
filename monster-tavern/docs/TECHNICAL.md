# Техническое устройство

Версия 0.1.0. Прототип написан на обычных HTML, CSS и JavaScript. Сцена рисуется Canvas 2D, интерфейс и перетаскивание — DOM и Pointer Events. Игрового движка, npm-зависимостей, сервера данных и сетевых API нет.

## Файлы

| Файл | Назначение |
|---|---|
| `index.html` | Структура страницы и исходный слой стилей |
| `layout.css` | Компоновка под размер окна, сцена и сбор предметов |
| `clarity.css` | Актуальная читаемость заказов, кнопки окон и полоса готовки |
| `assets/custom/sheet-3.png` … `sheet-10.png` | Восемь оригинальных пользовательских листов |
| `assets/custom/sprites.json` | Области 143 объектов на этих листах |
| `assets.js` | Генерируемые встроенные изображения и метаданные |
| `art.js` | Локальные Blob URL, DOM-иконки и отображение участков листов |
| `assembly.js` | Перенос предметов, состав заказа, готовка, окно трофея |
| `scene.js` | Геометрия помещения, размещение арта, персонажи и масштабирование |
| `dashboard.js` | Улучшения, персонал, карточки заказов, окна склада и рецептов |
| `game.js` | Состояние, экономика, гости, события, сохранение, главный цикл |
| `build.py` | Генерация `assets.js`, самостоятельного HTML и архива |
| `prepare_assets.py` | Повторный расчёт границ объектов на исходных листах; нужен Pillow |
| `smoke-test.cjs` | Проверка логики в Node.js с минимальными заглушками DOM |

Порядок скриптов важен: `assets.js` → `art.js` → `assembly.js` → `scene.js` → `dashboard.js` → `game.js`. Они используют общий контекст страницы, а не ES-модули. Основное состояние `state` и переменные сцены доступны соседним скриптам через этот контекст.

## Сборка и запуск

Для готового `Tavern.html` нужен только современный браузер. Для пересборки нужен Python 3 со стандартной библиотекой. Для проверки логики нужен Node.js; установка пакетов не требуется.

Из корня распакованного проекта:

```sh
python build.py
node smoke-test.cjs
python -m http.server 8765 --bind 127.0.0.1
```

Открыть `http://127.0.0.1:8765/index.html` для разработки или `http://127.0.0.1:8765/Tavern.html` для готовой сборки. Если порт занят, выбрать другой. Все пути сборки определяются относительно файлов проекта, а не исходной рабочей папки.

`Tavern.html` содержит код, стили и все PNG, работает без сетевых ресурсов. Его размер около 24 МБ обусловлен включением оригинальных изображений. Во время загрузки они преобразуются в локальные Blob URL, чтобы длинные data URL не нарушали работу CSS-переменных Chromium.

## Визуальная система

Логическая сцена — 1000 × 680. Размер Canvas подстраивается под контейнер и devicePixelRatio с ограничением 2. Геометрия растягивается по размерам области, а изображения корректируются для сохранения пропорций. Иконки используют те же исходные листы через CSS background-position. Карта, столы и маршруты заданы в коде.

На компьютере вся страница фиксирована по высоте окна; длинные списки имеют внутреннюю прокрутку. Ниже порога 900 CSS-пикселей используется вертикальная страница. Кнопка полного экрана вызывает браузерный Fullscreen API с подсказкой F11 при отказе.

## Жизненный цикл

`requestAnimationFrame` вызывает обновление симуляции, таймер задания и отрисовку. Шаг времени ограничен 0.08 секунды; это предотвращает большие скачки, но на очень низкой частоте кадров симуляция замедляется. UI мира обновляется примерно раз в 0.4 секунды. Готовка ведёт отдельный таймер внутри модального окна.

Основные ресурсы хранятся массивом из 12 чисел, а рецепты ссылаются на его индексы. Перестановка индексов без миграции нарушит существующие сохранения. Параметры экономики пока находятся непосредственно в JavaScript.

## Сохранение

Ключ localStorage: `monster-tavern-v1`; поле версии данных: `version: 1`. Это версия схемы сохранения, независимая от версии прототипа 0.1.0. Запись выполняется примерно каждые 5 игровых секунд, при закрытии окна задания, ряде покупок, скрытии вкладки и уходе со страницы.

Сохранение привязано к браузеру и origin, а для `file://` — к поведению конкретного браузера. Архив не содержит сохранение пользователя и не переносит его автоматически в новый адрес проекта. Если localStorage запрещён, игра работает, но показывает невозможность сохранения. Валидация загружаемых данных минимальна; развёрнутых миграций и защиты от ручного изменения нет.

## Что не входит в техническую проверку

Тест Node проверяет логику, но не изображает настоящий браузер, Pointer Events и CSS. Поэтому успешный тест не заменяет проверку переноса мышью и визуальную проверку. Матрица мобильных устройств и браузеров пока не выполнена. Подробные результаты и границы проверки находятся в [QA.md](QA.md).
